# Building a Voice-to-Text Keyboard Extension for iOS

## Introduction

In this technical blog, I'll walk you through my journey of building a custom iOS keyboard extension that uses voice transcription. This project was completed as part of an iOS internship assessment, and it challenged me to work with several iOS frameworks including App Extensions, AVFoundation, and network APIs.

## Project Overview

The goal was to create a custom keyboard that allows users to input text by speaking rather than typing. The workflow is simple but powerful:

1. User presses and holds a button
2. Audio is recorded continuously
3. Upon release, audio is sent to Groq's Whisper API
4. Transcribed text is inserted at the cursor position

## Technical Architecture

### Core Components

The project consists of three main technical components:

1. **Custom Keyboard Extension** - The UI and interaction layer
2. **Audio Recording System** - Capturing voice input
3. **API Integration** - Transcription via Groq's Whisper

### Technology Stack

- **UIKit** for the user interface
- **AVFoundation** for audio recording
- **URLSession** for API communication
- **Core Animation** for visual feedback

## Implementation Deep Dive

### 1. Setting Up the Keyboard Extension

Creating a keyboard extension in iOS requires specific configuration. The key is the `Info.plist` setup:

```xml
<key>NSExtension</key>
<dict>
    <key>NSExtensionPointIdentifier</key>
    <string>com.apple.keyboard-service</string>
    <key>NSExtensionPrincipalClass</key>
    <string>KeyboardViewController</string>
    <key>RequestsOpenAccess</key>
    <true/>
</dict>
```

The `RequestsOpenAccess` flag is crucial - it enables network access and microphone permissions, both essential for our use case.

### 2. Audio Recording Architecture

One of the most challenging aspects was implementing reliable audio recording in the constrained environment of a keyboard extension.

**Key Decisions:**

**Audio Format:** I chose M4A (MPEG-4 AAC) for several reasons:
- Better compression than WAV
- Native support on iOS
- Compatible with Whisper API
- Smaller file sizes for faster uploads

**Sample Rate:** 16kHz provides the optimal balance:
- High enough for clear speech recognition
- Low enough to minimize file size
- Industry standard for speech-to-text

**Audio Session Configuration:**

```swift
let audioSession = AVAudioSession.sharedInstance()
try audioSession.setCategory(.playAndRecord, 
                            mode: .default, 
                            options: [.defaultToSpeaker])
```

This configuration ensures the audio plays back through the speaker (not the earpiece) if needed, and properly handles the recording category.

### 3. Gesture Recognition

The press-and-hold interaction required careful implementation of `UILongPressGestureRecognizer`:

```swift
let longPress = UILongPressGestureRecognizer(
    target: self, 
    action: #selector(handleLongPress)
)
longPress.minimumPressDuration = 0.1 // Responsive but not accidental
```

The 0.1 second minimum prevents accidental triggers while still feeling immediate to the user.

### 4. Visual Feedback System

User feedback was critical for this interface. I implemented three distinct states:

**Idle State:**
- Blue circular button
- Microphone icon visible
- Status text: "Hold to record"

**Recording State:**
- Red circular button
- Pulsing animation
- Status text: "Recording..."

**Processing State:**
- Blue circular button returns
- Activity indicator
- Status text: "Processing..."

The pulsing animation uses `CAAnimationGroup` to create a smooth, eye-catching effect that clearly communicates active recording.

### 5. API Integration

The Groq Whisper API integration required careful handling of multipart form data:

```swift
let boundary = "Boundary-\(UUID().uuidString)"
request.setValue("multipart/form-data; boundary=\(boundary)", 
                forHTTPHeaderField: "Content-Type")
```

**Key Challenges:**

1. **Multipart Form Encoding:** Unlike simple JSON, audio uploads require multipart/form-data encoding with proper boundaries.

2. **Error Handling:** Network requests can fail in many ways:
   - No internet connection
   - API timeout
   - Invalid API key
   - Malformed response

3. **Memory Management:** Keyboard extensions have strict memory limits (~30MB). Files must be deleted immediately after upload.

### 6. Memory Optimization

Keyboard extensions are heavily memory-constrained. Here's how I addressed this:

**Temporary Storage:**
```swift
let tempDir = FileManager.default.temporaryDirectory
audioFileURL = tempDir.appendingPathComponent(
    "recording_\(Date().timeIntervalSince1970).m4a"
)
```

**Immediate Cleanup:**
```swift
if let url = audioFileURL {
    try? FileManager.default.removeItem(at: url)
}
```

Files are deleted as soon as transcription completes, preventing memory buildup.

## Challenges and Solutions

### Challenge 1: Keyboard Extension Permissions

**Problem:** Keyboard extensions have limited permissions by default.

**Solution:** Requesting "Full Access" enables microphone and network permissions. This required clear user communication about why it's necessary.

### Challenge 2: Testing Audio in Simulator

**Problem:** iOS Simulator doesn't support microphone input.

**Solution:** All testing had to be done on physical devices. I set up a workflow that allowed rapid iteration:
1. Code changes
2. Clean build
3. Run on device
4. Test immediately

### Challenge 3: Network Reliability

**Problem:** Network requests can fail unpredictably.

**Solution:** Implemented comprehensive error handling with user-friendly messages:
- "Network error" for connection failures
- "Microphone permission denied" for permission issues
- "Failed to transcribe" for API errors

### Challenge 4: User Feedback

**Problem:** Users need to know what the keyboard is doing at all times.

**Solution:** Every state has distinct visual and textual feedback:
- Haptic feedback on press/release
- Color changes during recording
- Pulsing animation
- Clear status messages

## Performance Considerations

### Audio Quality vs File Size

I tested several sample rates:
- 8kHz: Too low, poor transcription accuracy
- 16kHz: ✅ Optimal balance
- 44.1kHz: Unnecessarily large files, slower uploads

### Network Optimization

- 30-second timeout balances patience with UX
- Immediate response parsing
- Background queue for heavy operations

### UI Responsiveness

All UI updates happen on the main thread:
```swift
DispatchQueue.main.async {
    self?.handleTranscriptionResponse(...)
}
```

## Security Considerations

### API Key Management

**Development:**
Hardcoded for rapid testing (acceptable for assessment)

**Production Recommendation:**
```swift
// Use Keychain for secure storage
let keychain = KeychainSwift()
let apiKey = keychain.get("groq_api_key")
```

### Privacy

- Audio is never stored permanently
- Files deleted immediately after transcription
- No telemetry or tracking
- Clear privacy messaging to users
